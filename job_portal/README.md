# AI Job Portal — Python / Flask implementation

This is the implementation described in the project report **"Full-Stack Job Portal with AI-Based
Resume Screening and Candidate Matching"** (Samrudhi Vishal Dubal, MBA, SRM IST — mentor Ms. Anjana,
Qollabb). It follows the report's architecture (Fig. 3.1), database design (Table 3.3), screening
model (Section 3.7) and evaluation (Chapter IV).

## Features

- **Recruiters**: register, post jobs, view candidates ranked by AI match score with matched and
  missing skills, filter to scores ≥ 60, update application status, download resumes.
- **Job seekers**: register, search jobs, apply with a PDF / DOCX / TXT resume (max 5 MB), see their own
  match score, missing skills and application status.
- **Security**: Werkzeug password hashing, session-based login, role checks, file-type and size
  validation, recruiters can only see candidates for their own jobs.
- **AI screening engine** (`screening/`): resume parsing, a synonym-aware skill taxonomy, TF-IDF
  cosine similarity and a weighted, explainable 0–100 score.

## Project structure

```
job_portal/
  app.py                    Flask web application (routes, auth, SQLite)
  screening/
    parser.py               text extraction (pypdf, python-docx) + email, phone, experience, education, skills
    skills.py               skill taxonomy: ~50 canonical skills with synonyms (k8s -> kubernetes, ...)
    matcher.py              hybrid model + baseline methods (keyword, TF-IDF only, skill only)
  templates/                Jinja2 HTML pages
  static/style.css
  eval/
    generate_dataset.py     builds the labelled test set (150 resumes x 6 jobs, fixed seed)
    evaluate.py             reproduces Tables 4.2 - 4.9 (P@10, R@20, NDCG@10, Spearman, thresholds, ...)
  tests/                    functional tests from Table 4.1 + engine unit tests (pytest)
  seed_demo.py              loads a demo recruiter, six jobs and eight applicants
```

## How to run

```bash
cd job_portal
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python -m eval.generate_dataset    # creates eval/data/*.json
python seed_demo.py                # optional demo data
python app.py                      # open http://127.0.0.1:5000
```

Demo logins (after `seed_demo.py`): recruiter `hr@demo.com` / `demo123`; job seekers
`c0@demo.com` … `c7@demo.com` / `demo123`.

Set `SECRET_KEY` as an environment variable before deploying anywhere public.

## The match score (Section 3.7)

```
Match Score = 100 × (0.35 × Text + 0.40 × Skills + 0.15 × Experience + 0.10 × Education)
```

| Component  | How it is computed |
|------------|--------------------|
| Text       | TF-IDF (unigrams + bigrams, English stop words) cosine similarity between JD and resume, divided by 0.5 and capped at 1 |
| Skills     | required skills found in the resume (via synonyms) ÷ required skills in the JD |
| Experience | largest "N years" in the resume ÷ JD minimum experience, capped at 1 |
| Education  | resume level ÷ required level (diploma 1, bachelor 2, master/MBA 3, doctorate 4), capped at 1 |

The default shortlisting threshold is **60** (Table 4.6).

## Tests and evaluation

```bash
python -m pytest -q                # 17 tests (11 functional cases from Table 4.1 + engine tests)
python -m eval.evaluate --charts   # prints Tables 4.2-4.9, saves eval/results.json and eval/charts/*.png
```

Because the test dataset is regenerated by `generate_dataset.py`, the exact figures can differ
slightly from those printed in the report; the overall pattern (hybrid model best at the top of the
ranking, keyword screening most easily fooled by stuffed resumes, threshold 60 catching every strong
fit while cutting ~89% of the screening workload) is reproduced.
